[5] 修复前：P0-4 中断风暴的硬件证据（同一固件的上一版）
================================================================
现象：串口停在 "statemachine_init() OK" 后 25 s 静默，不复位。

PC 连续采样（每次 halt 后读）：
  pc = 0x08008c20   xpsr = 0x21000012   IPSR = 18  (= IRQ 2 RTC_TAMP)
  pc = 0x080043f0   xpsr = 0x01000012   IPSR = 18   (在 xTaskGetSchedulerState 内)
  pc = 0x080043f8   xpsr = 0x21000012   IPSR = 18
  pc = 0x08008bf8   xpsr = 0x61000012   IPSR = 18
  pc = 0x08008c20   xpsr = 0x21000012   IPSR = 18

addr2line:
  0x08008bfc -> RTC_TAMP_IRQHandler        (0x08008be8..0x08008c48)
  0x08008bf1 -> RTC_TAMP_IRQHandler

反汇编（卡住处）：
  08008be8 <RTC_TAMP_IRQHandler>:
    8008bec: bl   80043e8 <xTaskGetSchedulerState>
    8008bf0: movs r3, r0
    8008bf2: cmp  r3, #1                 ; taskSCHEDULER_NOT_STARTED == 1?
    8008bf4: bne.n 8008c30               ; 否 -> 走 HAL 处理路径
    8008bfa: movs r2, #0xCA
    8008bfc: str  r2, [r3, #36]          ; RTC->WPR = 0xCA   (停在这附近)
    ...
    8008c0a: ldr  r2, [r3, #92]          ; RTC->SCR  (偏移 0x5C)
    8008c12: orrs r2, r1                 ; | RTC_SCR_CWUTF (bit2)
    8008c14: str  r2, [r3, #92]
    ...                                  ; 随后 | RTC_SCR_CALRAF (bit0)
    8008c2c: str  r2, [r3, #36]          ; RTC->WPR = 0xFF

RTC 寄存器实测：
  40002800: 00221002 00260729 00007084 00000033   | TR DR SSR ISR
  40002810: 00007fff 00000000 40007704 00000000   | PRER WUTR CR -
  4000284c: 07007fdf 00000002 00000002 00000000   | ALRMBSSR SR MISR -
  4000285c: 00000000 00000000                     | SCR OR

  RTC_SR   = 0x02  → bit1 = RTC_SR_ALRBF（Alarm B 标志）唯一置位
  RTC_MISR = 0x02  → 该源中断使能
  RTC_CR   = 0x40007704 → bit8/9/10 = ALRAIE|ALRBIE|WUTIE 全开
  RTC_SCR  = 0     → 清除寄存器从未被写过  ← 根因所在

中断控制器：
  NVIC ISER(0xE000E100) = 0x10080084 → 使能 IRQ 2(RTC_TAMP) 7(EXTI4_15) 19(TIM14) 28(USART2)
  NVIC ISPR(0xE000E200) = 0x10080000 → TIM14 与 USART2 一直 pending 得不到服务
  NVIC IABR(0xE000E300) = 0

.noinit 故障记录 (0x20000438, 12 B)
  00000000 00000000 00000000   → 全 0 = 未发生失效安全捕获 / 不是复位循环

机制：RTC_Init() 里 RTC_TimerCreateMs(500, ...) 用 Alarm B 武装 500 ms 期限；
RTC_Init() 返回后 main() 还有 component/bus/param/power/CLI/telemetry 初始化
与全部 xTaskCreate()，远超 500 ms ⇒ Alarm B 在 vTaskStartScheduler() 之前到期
⇒ 进 ISR 的 taskSCHEDULER_NOT_STARTED 早退分支 ⇒ 只清 WUTF/ALRAF，漏 ALRBF
⇒ 标志寄存器只读、ALRBF 一直为 1 ⇒ 中断线持续拉高 ⇒ 退出即重入 ⇒ 死锁。

修法：templates/drivers/drv_rtc.c.j2 新增 rtc_clear_all_flags()
（掩码 CALRAF|CALRBF|CWUTF|CTSF|CTSOVF|CITSF，经 __HAL_RTC_CLEAR_FLAG 写 SCR），
三处调用点（RTC_Init 陈旧标志清理 / 使能中断前的解除残留 / ISR 早退分支）全部改走它；
初始化时补 HAL_RTC_DeactivateAlarm(A/B) 与 ALRA/ALRB/WUT 的 IT 失能。
修复后重新烧录 ⇒ 见 [2]，完整启动成功。

[7] 复验：稳态再采样（烧录后持续运行约 4 分钟后，同一固件）
================================================================
$ pyocd cmd -t stm32g0b1retx -c halt -c "reg pc" -c "reg xpsr" \
    -c "read32 0xE000E100 4" -c "read32 0xE000E200 4" -c "read32 0xE000E300 4" \
    -c "read32 0x40002850 8"  -c "read32 0x4000281C 4" -c "read32 0x4000285C 4" \
    -c "read32 0x20000438 12" -c "go"

pc    = 0x0800400a   ->  prvIdleTask  (tasks.c)   ← 调度器在跑，CPU 处于空闲任务
xpsr  = 0x61000000   ->  IPSR = 0                ← 不在任何异常上下文（对比修复前恒为 18）
sp    = 0x20002928                               ← 线程栈有效

NVIC ISER(0xE000E100) = 0x10080084  → IRQ 2(RTC_TAMP) 7(EXTI4_15) 19(TIM14) 28(USART2)，与修复前一致
NVIC ISPR(0xE000E200) = 0x00000000  ← 无 pending（修复前 0x10080000，TIM14/USART2 被饿死）
NVIC IABR(0xE000E300) = 0x00000000  ← 无 active

RTC_SR (0x40002850)   = 0x00000000  ← ALRBF 已清（修复前 0x00000002，根因消除）
RTC_MISR(0x40002854)  = 0x00000000  ← 无"使能且挂起"的中断源
RTC_CR (0x4000281C)   = 0x00000000  ← ALRAIE/ALRBIE/WUTIE 当前均关（500 ms 单次已消费并按需重臂）
RTC_SCR(0x4000285C)   = 0x00000000  ← 无待清标志

.noinit(0x20000438, 12 B) = 00 00 00 00 00 00 00 00 00 00 00 00
                            ← 全 0：运行 4 分钟未发生失效安全捕获、非复位循环

结论：P0-4 修复在真机稳态下成立 —— 无中断风暴、无待决中断、CPU 正常进入空闲任务。
